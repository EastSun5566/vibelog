# @vibelog/core

Build static blogs from content and a validated Presentation IR v2 design. Core
provides the builder, HackMD source, AI design providers, schema validation and
CSS compiler. Search, RSS, sitemap, per-post Markdown and `llms.txt` are built
into the template; they are not generated by an AI model.

For agent onboarding to hosted VibeLog, use **`@vibelog/cli`**, not core.

`@vibelog/core@beta`. The older `latest` tag is preserved for existing consumers;
this release requires the API migration below.

## Maintainer release gate

Core uses the independent `core-v<version>` tag and
[`core-release.yml`](https://github.com/EastSun5566/vibelog/blob/main/.github/workflows/core-release.yml).
It does not deploy production, publish the CLI, or create a monorepo release.

After the workflow is merged and shortly before the approved first release,
configure a trusted publisher for **`@vibelog/core`** in its npm package settings
(the CLI's configuration is separate). The first successful publish must occur
within two days; otherwise delete the expired connection and create a new one:

- Organization or user: `EastSun5566`
- Repository: `vibelog`
- Workflow filename: `core-release.yml`
- Environment: `npm`
- Allow direct `npm publish`; no `npm dist-tag` permission is needed.

Use GitHub-hosted runners and OIDC; do not add an npm token to GitHub secrets.
After verifying the first OIDC publish, set **Publishing access** to
**Require two-factor authentication and disallow tokens**. This blocks traditional
token publishing without affecting the trusted publisher.
The workflow requires the tagged commit to be on `main` with successful CI for
that exact SHA. Only after checking that gate and obtaining release approval,
create and push an annotated `core-v0.11.2` tag. Do not use `v0.11.2`, which belongs
to the application release workflow.

The workflow builds and packs once, tests that tarball in an isolated npm
project, dry-runs it, and publishes the same bytes to `beta` with provenance.
It then downloads the published tarball, compares its integrity, verifies that
`latest` is unchanged, and repeats the standalone smoke. A version cannot be
republished: if a post-publish check fails, verify the existing version rather
than moving the public tag or publishing different bytes under that version.

See the official [trusted publisher setup](https://docs.npmjs.com/trusted-publishers).

## Validate a design and compile CSS

Save as `design.mjs` and run `node design.mjs`:

```js
import { writeFile } from 'node:fs/promises';
import {
  DEFAULT_DESIGN_V2,
  validateBlogDesignSpecV2,
  compileDesignCss,
} from '@vibelog/core';

const candidate = structuredClone(DEFAULT_DESIGN_V2);
candidate.theme.typography.bodyFont = 'system-mono';
const design = validateBlogDesignSpecV2(candidate);
await writeFile('design.css', compileDesignCss(design));
```

Validation checks structure, references, placement and contrast. The AI tools
and agent contract share JSON Schema generated from the Zod definitions; JSON
Schema does not replace the runtime semantic checks. Designs can customize the
supported layout, typography, colors and presentation rules, not arbitrary CSS
or HTML.

## Build a static blog

Save as `build.mjs` and run `node build.mjs`. This example uses synthetic content,
requires no API key and does not call an AI provider:

```js
import { resolve, join } from 'node:path';
import {
  ContentSourceName, createDevBuilder, writeSourceSnapshot, buildBlog,
  DEFAULT_DESIGN_V2, validateBlogDesignSpecV2,
} from '@vibelog/core';

const root = resolve('my-blog');
const builder = createDevBuilder({
  root,
  contentSource: {
    name: ContentSourceName.HACKMD,
    getAuthor: async () => ({ name: 'Writer', bio: 'Notes on building things.' }),
    getPosts: async () => ({ posts: [{
      id: 'first', slug: 'first', title: 'First post',
      date: '2026-01-01T00:00:00Z',
      content: '## Hello\n\nMy first article. Inline math: $E=mc^2$.',
    }] }),
  },
});
await builder.prepare({ installDependencies: false });
const summary = await builder.fetchContent();
const sourceDir = join(root, 'source');
await writeSourceSnapshot(builder.vibelogDir, sourceDir, summary);
const workDir = join(root, 'build');
await buildBlog({
  sourceDir,
  design: validateBlogDesignSpecV2(DEFAULT_DESIGN_V2),
  workDir,
  outDir: join(workDir, 'dist'),
  site: 'https://writer.example.com',
});
```

Serve `my-blog/build/dist` with a static server. Use the real public site URL for
canonical links, feed and sitemap. The snapshot is separate from the build
workspace, so it can be reused with another validated design. For public HackMD
content, replace the synthetic `contentSource` with
`new HackMdSource('your-public-username')` imported from `@vibelog/core`.

`prepare({ installDependencies: false })` uses the installed package's template
runtime; the default `prepare()` instead installs template dependencies. The
renderer runs in a separate process, and failed builds keep the last successful
output.

## Migrating from the older npm API

This is an explicit API migration. There is no legacy compatibility shim.

| Earlier API | Current behavior |
| --- | --- |
| `StyleTransformer`, `createStyleTransformer`, `CssParser`, arbitrary CSS transformations | Removed. Start with validated IR v2 and `compileDesignCss`; old CSS cannot be automatically converted. |
| `FsSource`, `NotionSource`, `createContentSource` | Removed. `HackMdSource` remains; implement the `ContentSource` interface for another source. No substitute is provided for removed adapters. |
| `createDevServer` | Removed. Build static output and use your own static server. |
| `AiProvider.generate(prompt: string)` and CSS results | `generate(input: DesignProposalInput, context?)` returns complete validated `BlogDesignSpecV2`. |
| `DevBuilder.fetchContent(): Promise<void>` | Returns a `BuildContentSummary` used by `writeSourceSnapshot`. |
| Exported Zod 3 schemas | Zod 4 schemas. Consumers composing schemas must use Zod 4, or use exported validation functions. |

An AI input contains `blog: { title, description, author }`, `contentProfile`,
`currentDesign` and `prompt`. Optional context supplies a `sessionId` and abort
`signal`. Hosted generation remains separate from building a static blog.

The only additional public entrypoint is `@vibelog/core/migration-v1`. It converts
existing VibeLog theme/Presentation IR v1 data to IR v2. It is **not** a general
converter for old npm APIs, arbitrary CSS, sources or dev-server code.

For strict TypeScript checking without `skipLibCheck`, also install the optional
type peer referenced by pi-ai's Google SDK declarations:

```sh
npm install --save-dev @modelcontextprotocol/sdk@1.32.1
```

This is needed to resolve upstream declarations even when not using Google or
MCP. It is not a core runtime requirement; JavaScript builds work without it.
The standalone smoke checks both cases and composes core schemas with Zod 4.

## Math packaging and security

The package includes a self-contained internal math module with the existing
remark/rehype plugins and **KaTeX 0.18.2**. It retains MathML, `trust: false` and
invalid-math fallback. Consumers do not need a KaTeX override. Build-time checks
reject external npm imports and unexpected embedded KaTeX versions.

`dist/core/math-plugins.json` lists bundled dependency versions;
`dist/THIRD_PARTY_NOTICES.txt` contains their license notices. These files do not
add public JavaScript exports. Other runtime dependencies remain ordinary npm
dependencies: this packaging change is not a claim that all advisories are fixed.
The known `sprintf-js` dependency remains tracked in the repository's
[dependency review](https://github.com/EastSun5566/vibelog/blob/main/.github/dependency-review.md).
